# HU61.2 — Cambio de rol por ID en Spring

Verificación HTTP en una instancia local aislada de Spring Boot con H2 y dos cuentas de prueba. Endpoint: `PATCH /_internal/admin/usuarios/{idUsuario}/rol`. El ID de la ruta identifica al afectado; la identidad del actor proviene de la sesión Bearer. La clave interna se envía en `X-Internal-Admin-Key`.

| Caso | Resultado observado |
|---|---|
| Administrador con sesión, sin clave interna | 403 |
| Administrador con sesión, clave incorrecta | 403 |
| Clave correcta, sin sesión | 401 |
| Clave correcta, sesión de cliente | 403 |
| Administrador y clave correctos, ID inexistente | 404 |
| Administrador y clave correctos, rol `INVALIDO` | 400 |
| Administrador y clave correctos, usuario 2 de `CLIENTE` a `VENDEDOR` | 200; una nueva sesión del usuario devolvió `VENDEDOR` |

Tras las siete peticiones, la consulta a `registros_auditoria` por `accion = 'CAMBIO_ROL'` devolvió **una sola fila**: `usuario = admin-hu612@example.test` (actor), `usuario_afectado_id = 2` (destinatario). Los rechazos no generaron eventos de cambio de rol. La nueva columna admite `NULL` para otros eventos y registros históricos.
