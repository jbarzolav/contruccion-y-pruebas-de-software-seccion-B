# HU64.2 — Cambio solicitado: Mercado Pago de pruebas por vendedor

**Estado: pendiente de integración.** El simulador local de checkout sigue siendo la implementación existente y solo responde si se activa `app.checkout.simulador=true`. No usarlo como comprobante de un pago de Mercado Pago. No se ha conectado ninguna cuenta ni confirmado un cobro externo.

Para que cada vendedor cobre con su propia cuenta, Mercado Pago exige OAuth de tipo *authorization code*. La aplicación del marketplace requiere un `client_id`, un `client_secret` y una `redirect_uri` HTTPS pública, estática y registrada exactamente en Mercado Pago. **Aún falta esa URL**; el Access Token que entrega el panel al creador de la aplicación no sustituye los permisos OAuth de los demás vendedores. No poner tokens ni el secreto en Git, Android ni frontend.

Implementación acordada, cuando exista la URL registrada:

1. El vendedor autenticado inicia la vinculación desde la app; el backend genera `state` aleatorio, asociado a su `usuario.id`, con caducidad y un solo uso, y devuelve la URL de autorización de Mercado Pago. En entornos compatibles, usar PKCE S256. Nunca fiarse de un `vendedorId` recibido en el callback.
2. El callback HTTPS del backend verifica `state`, intercambia el `code` una sola vez con `/oauth/token` (con `test_token=true` para credenciales de prueba) y cifra el `access_token` y el `refresh_token` antes de guardarlos por vendedor. La clave de cifrado y `client_secret` viven solo en el entorno del backend. Renovar de forma atómica ambos tokens antes de expirar; el refresh token rota.
3. Checkout Pro crea la preferencia con el token OAuth del vendedor del pedido. El comprador abre el enlace en Mercado Pago; el backend no confía en botones de «aprobar», el navegador ni los parámetros de retorno para marcar `PAGADO`.
4. Confirmar cada transacción consultando a Mercado Pago desde el servidor (y procesar Webhooks con firma validada cuando haya URL pública). Validar vendedor, referencia única del intento, importe, moneda PEN y estado aprobado, con idempotencia; solo entonces consumir carrito, descontar stock y notificar. Definir cómo actuar ante reservas vencidas y pagos que lleguen tarde antes de habilitar cobros.
5. HU65.2 debe solicitar el reembolso real de prueba en Mercado Pago, verificar su resultado y reponer stock una sola vez. La UI de «Simular aprobación/fallo» de devoluciones es transitoria y no se debe mostrar como resultado externo verificado.

**Bloqueo actual:** obtener y registrar `redirect_uri` HTTPS pública y configurar `MP_CLIENT_ID`, `MP_CLIENT_SECRET` y una clave AES-GCM estable en el backend. No compartir valores secretos en chats ni commits. Sin esto, no se puede completar ni verificar la vinculación de vendedores.

Referencias: [OAuth de Mercado Pago](https://www.mercadopago.com.pe/developers/en/docs/security/oauth/creation), [renovación de tokens](https://www.mercadopago.com.pe/developers/en/docs/security/oauth/renewal) e [integración de marketplaces](https://www.mercadopago.com.pe/developers/en/docs/checkout-pro/how-tos/integrate-marketplace).
